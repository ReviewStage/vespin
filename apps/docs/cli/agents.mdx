Start, follow, message, and manage coding agents, and reach their branches, ports, shells, and browser tabs. Every command also takes the global flags `--json`, `-q`, `-w`, and `--url`, described in [CLI](/cli#scripts-and-coding-agents).

## vespin agent start

Start an agent on a task

```sh
vespin agent start [flags] <task>
```

| Argument or flag | What it does |
| --- | --- |
| `task string` | The task, by its id, its number, or its key such as ACME-42 |
| `--file, -F string` | The prompt, from a file or - for stdin |
| `--model string` | The model to run on, by its catalog id, with `--effort` |
| `--effort string` | The reasoning effort, with `--model` |
| `--cloud` | Run in the cloud |
| `--on string` | Run on one of your devices, by its name or id |
| `--branch string` | The branch to clone the agent's checkout at, already on GitHub (default: the repository's default branch) |
| `--follow` | Stream the agent's turn until it ends |
| `--wait` | Wait until the turn ends; the exit code says how |

```sh
# An agent in the cloud, on a branch already on GitHub
vespin agent start ACME-42 --branch fix/login --cloud

# An agent on a prompt from stdin, waited on
echo "Add a test for the redirect" | vespin agent start ACME-42 -F - --wait

# Choose the model, and stream the turn
vespin agent start ACME-42 --model anthropic/claude-opus-5.5 --effort high --follow
```

## vespin agent continue

Continue an agent as a new one on its task, handed its brief and transcript, as the app's Continue does; the agent is stopped, and the new one runs as you, on your own plan. --at forks it at a message instead, and it goes on

```sh
vespin agent continue [flags] <agent>
```

| Argument or flag | What it does |
| --- | --- |
| `agent string` | The agent's id |
| `--file, -F string` | A note handed to the new agent after the transcript, from a file or - for stdin |
| `--at string` | Fork at this assistant message of the agent's transcript, by its id (agent logs `--json`), instead of continuing: the agent goes on |
| `--model string` | The model to run on, with `--effort` (default: the agent's) |
| `--effort string` | The reasoning effort, with `--model` |
| `--cloud` | Run in the cloud |
| `--on string` | Run on one of your devices, by its name or id (default: where the agent runs) |
| `--follow` | Stream the agent's turn until it ends |
| `--wait` | Wait until the turn ends; the exit code says how |

```sh
# A new agent picks up where this one stopped, failed, or ran out of context
vespin agent continue <id>

# Continue in the cloud with a note, and wait on it
echo "Now add the tests" | vespin agent continue <id> -F - --cloud --wait

# Fork at one of its messages, and stream the new agent's turn
vespin agent continue <id> --at <message-id> --follow
```

## vespin agent list

List a task's agents, or the workspace's a page at a time, newest first

```sh
vespin agent list [flags] [<task>]
```

| Argument or flag | What it does |
| --- | --- |
| `task string` | The task, by its id, its number, or its key such as ACME-42 (optional) |
| `--offset integer` | How many of the workspace's agents to pass over: the nextOffset an earlier list printed |

```sh
# One task's agents
vespin agent list ACME-42

# The workspace's agents' ids
vespin agent list -q

# The workspace's next page, from the nextOffset a list printed
vespin agent list --offset 50
```

## vespin agent logs

Print an agent's transcript, or one of its workers' with --worker, or one call of it whole with --call; --follow streams the turn under way (with --json, the whole transcript once it ends)

```sh
vespin agent logs [flags] <agent>
```

| Argument or flag | What it does |
| --- | --- |
| `agent string` | The agent's id |
| `--follow, -f` | Stream the turn under way until it ends |
| `--worker string` | Read one of its workers' transcript instead, by the toolCallId of the call that started it (agent logs `--json`) |
| `--call string` | Print one call whole, its input and its output, by its toolCallId (agent logs `--json`) |

```sh
# The transcript so far
vespin agent logs <id>

# Stream the turn live
vespin agent logs <id> --follow

# A worker's transcript
vespin agent logs <id> --worker <callId>

# One call, its output whole
vespin agent logs <id> --call <callId>
```

## vespin agent send

Message an agent; it reads it at its next step, or starts a turn on it

```sh
vespin agent send [flags] <agent>
```

| Argument or flag | What it does |
| --- | --- |
| `agent string` | The agent's id |
| `--file, -F string` | The message, from a file or - for stdin |
| `--queue` | Queue it behind the agent's turn, as ⌘↩ does, rather than steer the turn under way; only the agent's starter queues, and a paused queue sends nothing until `vespin agent queue resume` |
| `--message-id string` | With `--queue`, the queued message's id, a UUID you mint, so a script addresses it with `vespin agent queue` even where this send's answer was lost; sent again under the same id while that message still waits, it queues nothing more, though once it went or was deleted it queues again |

```sh
# A follow-up from stdin
echo "Also update the README" | vespin agent send <id> -F -

# Queued to go once the turn under way ends
vespin agent send <id> --queue -F next.md
```

## vespin agent update

Change an agent, one change a call: rename it, move it to another model, pin or unpin it, archive it or bring it back, or switch its MCP servers off

```sh
vespin agent update [flags] <agent>
```

| Argument or flag | What it does |
| --- | --- |
| `agent string` | The agent's id |
| `--title string` | Rename it; empty clears the title, so the model's name shows |
| `--model string` | Move it to this model from its next step, with `--effort` |
| `--effort string` | The reasoning effort, with `--model` |
| `--pin` | Pin it in your sidebar; the pin is yours alone |
| `--unpin` | Unpin it from your sidebar |
| `--archive` | Archive it, stopping a turn still running; its transcript, branch, and pull request stay |
| `--unarchive` | Bring an archived agent back |
| `--reason string` | Why it is archived, shown on its archived banner, with `--archive` |
| `--disabled-servers string` | The MCP servers switched off for it, comma-separated, replacing the list; "" switches every one on |

```sh
# Rename it
vespin agent update <id> --title "Fix the login"

# Move it to another model from its next step
vespin agent update <id> --model anthropic/claude-opus-5.5 --effort high

# Archive it, saying why
vespin agent update <id> --archive --reason "Its pull request merged"

# Switch two MCP servers off for it
vespin agent update <id> --disabled-servers linear,notion
```

## vespin agent forward

Serve an agent's cloud ports on localhost until Ctrl-C or until its sandbox stops

```sh
vespin agent forward [flags] <agent> [<port...>]
```

| Argument or flag | What it does |
| --- | --- |
| `agent string` | The agent's id |
| `port... integer` | The sandbox's ports to forward (default: the ones it listens on now) (optional) |
| `--local integer` | The local port to serve the one port named on (default: the same) |

```sh
# Every port the sandbox listens on now, each on the same local port
vespin agent forward <id>

# The ports named
vespin agent forward <id> 3000 5173

# The sandbox's 3000 on localhost:3001
vespin agent forward <id> 3000 --local 3001
```

## vespin agent wait

Wait until an agent's turn ends: exit 0 when it completed, 5 when it failed or was stopped, 6 on --timeout

```sh
vespin agent wait [flags] <agent>
```

| Argument or flag | What it does |
| --- | --- |
| `agent string` | The agent's id |
| `--timeout integer` | Give up after this many seconds, exiting 6 |

```sh
# Block until the turn ends
vespin agent wait <id>

# Bring the work here once it completed
vespin agent wait <id> --timeout 600 && vespin agent checkout <id>
```

## vespin agent pr

Change an agent's pull request on GitHub as you: mark it ready, turn it back into a draft, merge it, or turn auto-merge on or off

```sh
vespin agent pr [flags] <agent> <change>
```

| Argument or flag | What it does |
| --- | --- |
| `agent string` | The agent's id |
| `change choice` | ready, draft, merge, or auto-merge |
| `--number integer` | Another pull request of the agent's repository, by its number |
| `--method choice` | How a merge or auto-merge merges (default: the first the repository allows) (choices: merge, squash, rebase) |
| `--head string` | The head commit a merge or auto-merge is made against (default: the head now) |
| `--off` | With auto-merge, turn it off |

```sh
# Mark the draft ready for review
vespin agent pr <id> ready

# Squash and merge now
vespin agent pr <id> merge --method squash

# Merge once its checks pass
vespin agent pr <id> auto-merge

# Turn auto-merge off
vespin agent pr <id> auto-merge --off
```
