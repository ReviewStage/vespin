---
title: "MCP tools"
description: "Every tool Vespin MCP offers, with its inputs"
---

Vespin MCP offers these tools to any agent you connect. Each acts as you, with your permissions, so it allows and refuses exactly what the app does. To connect an agent, see [MCP](/vespin-mcp).

Each tool answers JSON text. A refusal comes back marked as an error, with `status: "rejected"` and why. A tool that lists, makes, or changes something of a workspace takes its slug as `workspace`, from `list_workspaces`, even where you belong to only one. A call that names a task, agent, or automation by its id may leave it out, since the id settles the workspace; a task named by its key, such as ACME-42, takes it.

### update_task

Changes a task's name, repository, status, priority, assignee, pin, section, parent, or blocks. Marking it done or canceled withdraws its open asks and archives its agents: idle ones at once, and working ones as their turns end. Moving it off done or canceled brings those agents back, but their asks stay withdrawn.

| Input | Type | Description |
| --- | --- | --- |
| `workspace` | string | The workspace the task stands in, by the slug list_workspaces answered: required with a key, and with an id the workspace that must hold the task; leave it out with an id for whichever workspace it stands in. (1–48 characters) |
| `taskId` | string, required | The task, by its id as list_tasks or list_agents answered it, or by its key, such as ACME-42. (1–64 characters) |
| `name` | string | Its new name, as the sidebar shows it. (1–200 characters) |
| `repository` | string or null | The GitHub repository its agents work in, as owner/name, which the workspace's GitHub installation must reach; null for none. |
| `pinned` | boolean | true to pin it in the member's sidebar, false to unpin it; their pin alone, no other member's. |
| `status` | `backlog` \| `todo` \| `in-progress` \| `done` \| `canceled` | Where the task now stands. |
| `priority` | `none` \| `urgent` \| `high` \| `medium` \| `low` | How much the task matters; none for a task no one has weighed yet. |
| `assignee` | string or null | The member the task is assigned to, who is on it now, by their mention link as list_tasks or another read names them, `[@Name](https://vespin.dev/&lt;workspace&gt;/person/&lt;id&gt;)`, or its address alone; a member of the task's workspace. null for no one. |
| `sectionId` | string or null | The sidebar section the member keeps it in, by the id list_tasks or create_section answered; it leaves the section it stood in and lands at the top of this one. null takes it out of its section, back under Tasks. |
| `parentTaskId` | string or null | The task to make it a child of, by the id list_tasks answered or its key, such as ACME-42: a task of your workspace working in the same repository, and neither this task nor one of its sub-tasks; where its agents run stays its own. null takes it out from under its parent, to stand at the top. |
| `blockedBy` | object | Its blocked-by (the tasks it waits on), changed: tasks to add and tasks to take away, each a task of your workspace. |
| `blocks` | object | Its blocks (the tasks that wait on it), changed: tasks to add and tasks to take away, each a task of your workspace. |

### start_agent

Starts an agent on a task, or from another agent on its task. Make a new task first with `create_task`. Answers once its session opens, which can take a minute or two. The agent doesn't report back to the caller. No start names who pays: each turn of a cloud agent runs on the first of your subscriptions and API keys for the model's provider that has room (where none has, your first API key, or with no key the subscription whose limit resets soonest), and moves to the next when one hits its limit, which can switch between a subscription and a key. An agent on a device runs on that machine's own login, whatever you keep.

| Input | Type | Description |
| --- | --- | --- |
| `workspace` | string | The workspace the task stands in, by the slug list_workspaces answered: required with a key, and with an id the workspace that must hold the task; leave it out with an id for whichever workspace it stands in. (1–48 characters) |
| `taskId` | string, required | The task to start the agent on, by the id list_tasks answered, or by its key, such as ACME-42, with the workspace it stands in; with from, the task of the agent it starts from. (1–64 characters) |
| `prompt` | string | What the agent should do, typed to it as its first message: everything it needs to start on its work, or the developer's words where they named the job. Every start takes one but a start from another agent, which takes none. (1–64000 characters) |
| `note` | string | Everything else the agent should hear as it starts (what to start with, what to watch out for, what to leave alone), handed to it after the prompt in the same first message; leave it out where there is nothing beyond the prompt. (1–64000 characters) |
| `title` | string | The agent's title from the start, how the developer sees it named, such as the pull request it will open; leave it out to have it named from what it is told. (1–80 characters) |
| `branch` | string | The branch of the task's repository to clone the agent's checkout at and cut its own branch from, such as the repository's default branch or the head branch of a pull request it builds on; it must already be on GitHub. Required on a task with a repository, except with from; leave it out for a task with no repository or a start from another agent. (1–255 characters) |
| `model` | string | The model to run on, by its catalog id (such as anthropic/claude-opus-5.5), as list_models lists it. Every start names it but one with from, which runs on the model of the agent it starts from unless it names another. (1–200 characters) |
| `effort` | string | The reasoning effort, as the model lists it (such as high); given with the model or not at all. (1–200 characters) |
| `permissionMode` | string, required | How the agent's tool calls are answered: full_access runs every one unasked, ask asks a member before a file edit or a shell command, and auto leaves each to the harness's own review, which asks where it cannot decide. Every start names it, one with from included. (full_access, ask, or auto) |
| `runsOn` | object | Where the agent runs: &#123;"machine":"vercel"&#125; for the cloud, &#123;"machine":"device","device":"&lt;name&gt;"&#125; for one of the member's own devices (a Mac or a host) by its name, or &#123;"machine":"device","deviceId":"&lt;id&gt;"&#125; by its id; it must be online, and a name matching none of those devices, or several, is refused with them listed. list_machines lists each place with the runsOn to pass. Every start names it but one with from, which runs where the agent it starts from runs unless it names another place, which moves it there. |
| `from` | object | Another agent of your workspace to take over from, on its own task: the new agent is handed its brief, its transcript (with Vespin's summary of the steps that do not fit), and a copy of its work, runs on its model unless you name one, and hears the note after them; it takes no prompt and no branch. mode continue continues the agent, which is stopped; mode fork forks it at messageId, and it goes on. |

### message_agent

Sends an agent a message as you, or queues it behind the agent's turn.

| Input | Type | Description |
| --- | --- | --- |
| `agentId` | string, required | The agent's id, as list_agents answered it. (1–36 characters) |
| `text` | string, required | What to tell the agent, as the member's own words: it reads them as a message the member typed in its composer. (1–16000 characters) |
| `queue` | boolean, required | false to steer it into the turn under way, as the composer's ↩ would, or start a turn on an idle agent; true to queue it behind the agent's turn, as the composer's ⌘↩ would: it waits unsent, and goes as the member's next message once the turn and every message queued before it are over, at once where the agent stands idle. Any member who may message the agent queues to it. |

### archive_agent

Archives an agent: it is stopped first and its open asks are withdrawn, then it leaves every list but the archived ones and takes no message. Its transcript, branch, and pull request stay, but an agent on a device has its folder removed there, so work it never pushed is lost. An agent still starting is refused.

| Input | Type | Description |
| --- | --- | --- |
| `agentId` | string, required | The agent's id, as list_agents answered it. (1–36 characters) |
| `reason` | string, required | Why it is archived, in a short sentence its archived banner shows beside the member's name, such as its pull request having merged. (1–500 characters) |

### unarchive_agent

| Input | Type | Description |
| --- | --- | --- |
