title: "MCP tools"
description: "Every tool Vespin MCP offers, with its inputs"
---

Vespin MCP offers these tools to any agent you connect. Each acts as you, with your permissions, so it allows and refuses exactly what the app does. To connect an agent, see [MCP](/vespin-mcp).

Each tool answers JSON text. A refusal comes back marked as an error, with `status: "rejected"` and why. Where you belong to several workspaces, a tool that takes `workspace` needs its slug, from `list_workspaces`.

## Workspaces and members

### list_workspaces

Your workspaces: each one's id, slug, name, and your role. Call it first.

No inputs.

### create_workspace

Creates a workspace you own.

| Input | Type | Description |
| --- | --- | --- |
| `name` | string, required | The new workspace's name, at most 64 characters, its ends trimmed. (1–64 characters) |

The workspace's members, owners first, with each one's role, and former members.

| Input | Type | Description |
| --- | --- | --- |
| `workspace` | string | The workspace to list, by the slug list_workspaces answered; leave it out where the member belongs to one workspace alone. (1–48 characters) |

Sets or removes the workspace's photo. Owners and admins only.

| Input | Type | Description |
| --- | --- | --- |
| `workspace` | string | The workspace whose photo to set, by the slug list_workspaces answered; leave it out where the member belongs to one workspace alone. (1–48 characters) |

## Tasks

### list_tasks

The workspace's tasks, newest first, 50 a page, and your sidebar sections.

| Input | Type | Description |
| --- | --- | --- |
| `workspace` | string | The workspace to list, by the slug list_workspaces answered; leave it out where the member belongs to one workspace alone. (1–48 characters) |

| `status` | `backlog` \| `todo` \| `in-progress` \| `done` \| `canceled` | Only the tasks that stand here; leave it out for all. |
| `assignee` | string or null | Only the tasks assigned to this member, by their mention link, or null for the tasks no one is assigned to; leave it out for all. |
| `offset` | integer | How many of the matching tasks to pass over, newest first: the nextOffset an earlier list answered, to read the next page; leave it out for the first. (at least 0) |

### create_task

Creates a task you own, with no agent on it.

| Input | Type | Description |
| --- | --- | --- |
| `workspace` | string | The workspace to list, by the slug list_workspaces answered; leave it out where the member belongs to one workspace alone. (1–48 characters) |
| `name` | string, required | The task's name, as the developer would name it in the sidebar. (1–200 characters) |
| `repository` | string or null | The GitHub repository its agents work in, as owner/name, which the workspace's GitHub installation must reach; null or left out for none, or the parent's where you give a parent. |
| `brief` | string | The developer's own words about the task, which Vespin is handed when they open a call on it; their words where they gave them, left out otherwise. (up to 16000 characters) |
| `status` | `backlog` \| `todo` \| `in-progress` \| `done` \| `canceled` | Where the task stands: backlog for work filed for later; todo where left out. |
| `priority` | `none` \| `urgent` \| `high` \| `medium` \| `low` | How much the task matters; none for a task no one has weighed yet. |
| `assignee` | string or null | The member the task is assigned to, who is on it now, by their mention link as list_tasks or another read names them, `[@Name](https://vespin.dev/&lt;workspace&gt;/person/&lt;id&gt;)`, or its address alone; a member of the task's workspace. null for no one. |
| `parentTaskId` | string | The task to make it a child of, by the id list_tasks answered: a task of your workspace, whose repository it works in. Left out, it stands at the top. (1–36 characters) |
| `subTaskIds` | array of string | Its sub-tasks (the tasks it is the parent of), by the id list_tasks answered, each a task of your workspace with no parent yet, working in one repository with it, which it takes, so leave repository out. Left out, it has none. (up to 50 items) |
| `blockedBy` | array of string | Its blocked-by (the tasks it waits on), by the id list_tasks answered, each a task of your workspace, such as a sibling whose work comes first. Left out, it waits on none. (up to 50 items) |
| `blocks` | array of string | Its blocks (the tasks that wait on it), by the id list_tasks answered, each a task of your workspace. Left out, none waits on it. (up to 50 items) |

### update_task

Changes a task's name, repository, status, priority, assignee, pin, section, parent, or blocks. Marking it done withdraws its open asks.

| Input | Type | Description |
| --- | --- | --- |
| `taskId` | string, required | The task's id, as list_tasks or list_agents answered it. (1–36 characters) |
| `name` | string | Its new name, as the sidebar shows it. (1–200 characters) |
| `repository` | string or null | The GitHub repository its agents work in, as owner/name, which the workspace's GitHub installation must reach; null for none. |
| `pinned` | boolean | true to pin it in the member's sidebar, false to unpin it; their pin alone, no other member's. |
| `status` | `backlog` \| `todo` \| `in-progress` \| `done` \| `canceled` | Where the task now stands. |
| `priority` | `none` \| `urgent` \| `high` \| `medium` \| `low` | How much the task matters; none for a task no one has weighed yet. |
| `assignee` | string or null | The member the task is assigned to, who is on it now, by their mention link as list_tasks or another read names them, `[@Name](https://vespin.dev/&lt;workspace&gt;/person/&lt;id&gt;)`, or its address alone; a member of the task's workspace. null for no one. |
| `sectionId` | string or null | The sidebar section the member keeps it in, by the id list_tasks or create_section answered; it leaves the section it stood in and lands at the top of this one. null takes it out of its section, back under Tasks. |
| `parentTaskId` | string or null | The task to make it a child of, by the id list_tasks answered: a task of your workspace working in the same repository, and neither this task nor one of its sub-tasks; where its agents run stays its own. null takes it out from under its parent, to stand at the top. |
| `blockedBy` | object | Its blocked-by (the tasks it waits on), changed: tasks to add and tasks to take away, each a task of your workspace. |
| `blocks` | object | Its blocks (the tasks that wait on it), changed: tasks to add and tasks to take away, each a task of your workspace. |

| Input | Type | Description |

| `from` | `blocked-by` \| `blocks` \| `sub-task` \| `parent`, required | How the other task stands to the task now: blocked-by (the other blocks it), blocks (it blocks the other), sub-task (the other is its child), or parent (the other is its parent). |
| `to` | `blocked-by` \| `blocks` \| `sub-task` \| `parent`, required | How the other task stands to the task once moved, in the same words as from, and another kind than from. |

### start_agent

Starts an agent on a task, on a new task, or from another agent. Answers once its session opens, which can take a minute or two. The agent doesn't report back to the caller.

| Input | Type | Description |
| --- | --- | --- |
| `workspace` | string | Where you name no taskId and no from, the workspace of the task made for the agent, by the slug list_workspaces answered; leave it out where the member belongs to one workspace alone. (1–48 characters) |
| `taskId` | string | The task to start the agent on, by the id list_tasks answered; leave it out to start it on a new task made for it. (1–36 characters) |
| `repository` | string or null | Where you name no taskId and no from, the GitHub repository of the task made for the agent, as owner/name, which the workspace's GitHub installation must reach; null or left out for none. A task's agent works in the task's own. |
| `prompt` | string | What the agent should do, typed to it as its first message: everything it needs to start on its work, or the developer's words where they named the job. Every start takes one but a start from another agent, which takes none. (1–64000 characters) |
| `note` | string | Everything else the agent should hear as it starts (what to start with, what to watch out for, what to leave alone), handed to it after the prompt in the same first message; leave it out where there is nothing beyond the prompt. (1–64000 characters) |
| `title` | string | The agent's title from the start, how the developer sees it named, such as the pull request it will open; leave it out to have it named from what it is told. (1–80 characters) |
| `branch` | string | The branch of the task's repository to clone the agent's checkout at and cut its own branch from, such as the head branch of a pull request it builds on; it must already be on GitHub. Leave it out for the repository's default branch. (1–255 characters) |
| `model` | string | The model to run on, by its catalog id (such as anthropic/claude-opus-5.5); leave it out with the effort for the member's default. (1–200 characters) |
| `effort` | string | The reasoning effort, as the model lists it (such as high); given with the model or not at all. (1–200 characters) |
| `runsOn` | object | Where the agent runs: &#123;"machine":"vercel"&#125; for the cloud, or &#123;"machine":"device","device":"&lt;name&gt;"&#125; for one of the member's own devices (a Mac or a host) by its name, in any case, or &#123;"machine":"device","deviceId":"&lt;id&gt;"&#125; by its id, which must be registered and online; a name that matches none of the member's devices, or more than one, is refused with their devices listed by name, id, and whether each is online. With from, another place than that agent's moves it there. Leave it out for where the agent it starts from runs, with from; else where the member's newest agent on the task runs; else where the member last chose to run one; else the cloud. |
| `from` | object | Another agent of your workspace to take over from, on its own task: the new agent is handed its brief and its transcript (with Vespin's summary of the steps that do not fit) and a copy of its work, runs on its model unless you name one, and hears the note after them; it takes no prompt and no branch. Without messageId it continues the agent, which is stopped; with one it forks the agent at that message, which goes on. |

### message_agent

| Input | Type | Description |

| `queue` | boolean | true to queue it behind the agent's turn, as the composer's ⌘↩ would, rather than steer it into the turn under way: it waits unsent, and goes as the member's next message once the turn and every message queued before it are over, at once where the agent stands idle. Any member who may message the agent queues to it. |
