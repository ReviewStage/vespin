---
title: "How Vespin isolates coding agents"
description: "What a cloud agent's sandbox holds and can reach"
---

Each cloud agent runs in its own [Vercel Sandbox](https://vercel.com/docs/vercel-sandbox), with its own checkout of the repository. Agents on your own machines aren't isolated; see [Where agents run](/where-agents-run).

## The sandbox

- One sandbox per agent. Workers an agent starts share its sandbox.
- The checkout is on the sandbox's own drive, beside the default branch of every repository your workspace connects.
- The agent has `sudo`. To approve each tool call, set **Default permissions** in **Settings › Agents** to **Ask for approval** (Claude Code only).

## Branches and pull requests

Agents are told to push to an `agent/…` branch, open a pull request, and not merge unless asked. Vespin doesn't enforce this, and an agent's GitHub access can write to the repository. To require a pull request, protect your default branch on GitHub.

## Credentials

| Credential | In the sandbox |
| --- | --- |
| GitHub App token | No. Added at the sandbox's firewall to requests to GitHub. Scoped to the agent's repositories: contents and pull requests (write), checks (read). Expires within an hour. |
| GitHub personal access token | No. Added at the firewall, only for the task's repository. |
| Your Vespin sign-in | No |
| Claude plan token, Anthropic or OpenAI API key | No. A placeholder, replaced at the firewall. |
| ChatGPT plan token | Yes |
| Workspace environment variables | Yes |
| Integrations | No. Reached through Vespin, with whatever access you granted. |

The agent can read anything in the sandbox, so it can reach the model and the transcript.

## Network

The sandbox can reach the internet. The firewall adds credentials; it doesn't block hosts.

An agent can run a command on its task assignee's Mac with `run_on_mac`, as that Mac's **Let agents run commands on this Mac** setting allows. The default is **Ask every time**.

Workspace members who can see an agent can message it, open a terminal in its sandbox, and open ports it shares. For an agent using your own GitHub token, only you can.

## Lifetime

- A sandbox stops after 5 idle minutes and keeps its disk.
- It's deleted after 7 days unused, or when you delete its agent or task. Archiving doesn't delete it.
